# features/finance/manage-group

- **`finance/manage-group`**: `/finance` 설정 탭의 그룹 멤버·초대. kista-api는 **1인 1그룹 정책**(개인 그룹 자동생성 없음)이라 `useFinanceGroupsQuery()`는 0개(무그룹=개인) 또는 1개(그룹 소속)만 반환하고 `FinanceGroup`에 `personal`·`name` 필드가 없다 — "그룹 소속 여부"(`groups.length`) 자체로 개인/그룹을 판정한다. `GroupManager`가 `groups`를 한 번만 구독하고, 그룹이 있으면 `GroupSection`(멤버 목록+탈퇴)을 렌더하며 없으면 초대 발급 안내만 보여준다 — 자식이 같은 쿼리를 다시 구독하지 않는다. **무그룹 유저가 초대를 발급하는 시점에 kista-api가 그 자리에서 새 그룹을 만들고 본인을 OWNER로 등록한다**(`POST /groups/{id}/invitations`의 path `id`는 이 경우 서버가 무시 — `GroupManager`가 무그룹일 때 `InviteDialog`에 `me.id`를 자리채움 값으로 넘긴다). 발급·수락·탈퇴·추방 mutation의 `financeKeys.all` 무효화는 `docs/agents/finance.md`의 그룹 스코프 항목 참고. 그룹 탈퇴·추방 시 데이터의 `group_id`는 **이관되지 않는다**(kista-api `leaveGroup`) — 탈퇴자는 더 이상 조회할 수 없고 남은 멤버는 계속 조회하므로, 안내 문구는 "더 이상 접근 불가"다. OWNER가 나가면 서버가 남은 멤버 중 가장 먼저 가입한 사람을 자동 승계한다. 1인 1그룹 정책상 이미 그룹에 소속된 유저는 다른 그룹 초대를 수락할 수 없어(서버가 거부) `AcceptInvitationForm`은 무그룹일 때만 노출한다. `isOwner` 게이팅은 `GroupSection`이 멤버 목록에서 내 role을 찾아 판정하고, 발급된 코드는 재조회가 안 되므로 다이얼로그가 열려 있는 동안만 표시하고 복사 버튼+경고 문구를 둔다. `AcceptInvitationForm`은 코드 입력 후 수락만 처리한다(코드를 본인이 직접 입력하는 흐름이라 거절 버튼 없음).
