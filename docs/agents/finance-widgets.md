# 가계부(finance) — widgets

공통 도메인 규칙은 docs/agents/finance.md

## widgets

- **`/finance`(가계부) 탭 구조**: 5탭(자산/수입/소비/저축/설정)이 각각 실제 라우트다 — `/finance`(자산, 첫 탭)·`/finance/income`·`/finance/expense`·`/finance/saving`·`/finance/settings`, 전부 `app/(main)/finance/(dashboard)/` 라우트 그룹(URL엔 드러나지 않음) 아래에 있다. `(dashboard)/layout.tsx`(Server)가 `assetSnapshots`/`monthlyClosing`/`financeGroupList` 공통 prefetch+`HydrationBoundary`와 `FinanceHeader`(client, 탭바+`PageHeader`, 활성 탭에 따라 actions 분기)를 소유하고, `/finance/new`·`/finance/bulk-register`·`/finance/[id]/edit`는 이 그룹 밖 형제 라우트라 탭 UI 영향을 받지 않는다(통계 메뉴와 동일 패턴, `docs/agents/architecture.md` 참고). `(dashboard)/page.tsx`가 자산 탭(5개 자산 위젯, `NewAssetButton`)을 담당하고, `settings/page.tsx`는 `widgets/asset-settings/AssetSettingsPanel`만 렌더한다. 수입/소비/저축 3탭(`(dashboard)/(flow)/income|expense|saving/page.tsx`)은 `widgets/finance-summary`·`widgets/finance-budget-progress`(2026-08부터 INCOME/EXPENSE/SAVING 전부 허용, 셋 다 예산 대비 렌더)·`widgets/finance-trend`·`widgets/finance-record-list`를 이 순서로, `type: FinanceCategoryType` prop 하나로 재사용한다(탭별 전용 위젯을 만들지 않는다) — 세부 데이터 흐름(12개월 윈도우 쿼리·카테고리 인덱스)은 `finance.md`의 `## entities`의 거래내역·예산 항목 참고. 기간 상태(`Period = {month, mode}`)는 `(flow)/useFinanceFlowData.ts` 공유 client 훅이 URL 쿼리(`?month=&mode=`)에 실어 관리한다 — 서브라우트 전환으로 세 탭이 더 이상 한 컴포넌트가 아니라 React state 공유가 불가능해졌고, React Query 캐시는 전역이라 쿼리 결과 자체는 동일 키로 자동 공유되므로 탭 간 진짜로 이어줘야 하는 값은 이 period뿐이다. `PageHeader` actions는 `FinanceHeader`가 활성 라우트로 분기한다 — 자산 탭은 `NewAssetButton`, 수입/소비/저축 탭은 "예산 관리" 링크(`/finance/budgets/{slug}` 인터셉팅 라우트, 해당 탭 type 고정 — 모달이 떠 있는 동안에도 배경 헤더는 원래 탭 기준으로 판정)와 `NewTransactionButton`(`features/finance/save-transaction`, "거래내역 등록")이 나란히 노출된다
- **`asset-overview`/`asset-trend`/`asset-composition`/`asset-record-check`/`asset-record-list`**: 자산 탭을 구성하는 5개 슬라이스. 위젯끼리 cross-import가 금지돼 있고 Server Component는 함수를 prop으로 넘길 수 없어, `asset-overview`(월 선택 UI)와 `asset-record-check`(선택된 월 기준 점검)가 공유하는 "기준 월" 상태는 `app/(main)/finance/(dashboard)/page.tsx`(자산 탭 페이지 자체, app 레이어)가 소유하고 각 위젯에 `month`/`onMonthChange` prop으로 흘려보낸다 — `market-holiday-calendar`류의 `marketPanels` slot 패턴과 같은 이유의 같은 해법이다. `asset-trend`·`asset-composition`도 같은 `month` 상태를 받아(`AssetTrend`/`AssetComposition` Shell → Inner) 집계 창의 끝을 선택된 월로 앵커링한다(`calcMonthlyTrend`/`calcComposition`의 `endMonth` 인자) — 값이 없으면 최신 기록 기준(과거 동작)으로 폴백한다. 집계 창 길이는 카드 헤더(`CardAction`)의 `shared/ui/SegmentedToggle` 기간 선택(12/24/36개월/전체, `MONTHLY_TREND_RANGE_OPTIONS`)으로 고르며, `'all'`은 `monthsLimit=Infinity`로 넘겨 기록 전체 월을 쓴다. 기간 상태(`trendMonths`, 연간 차트는 `trendYears` 5/10년/전체)는 `FinancePeriodProvider`가 소유해 자산 두 차트와 수입/소비/저축 월간 추이가 공유하고 탭 전환 후에도 유지된다(새로고침엔 초기화). 수입/소비/저축 추이는 요약·내역용 `flowWindow`와 별개로 `trendWindow(period, range)` 쿼리를 쓴다(`'all'`은 `from` 없이 조회, 월간 12개월은 `windowRange`와 같은 키라 캐시 공유) — 로딩도 분리돼 기간 변경 시 추이 카드만 스켈레톤이 된다. `asset-trend`(recharts LineChart)·`asset-composition`(recharts 스택 BarChart ×2)은 각각 Shell + `next/dynamic({ ssr: false })` Inner 분리 구조이며, `react-doctor/prefer-dynamic-import` 룰은 파일 간 도달 가능성을 보지 않고 recharts 정적 import를 항상 감지하므로 기존 recharts 위젯과 동일하게 `// eslint-disable-next-line react-doctor/prefer-dynamic-import`를 import 직전 줄에 둔다(설명 주석은 disable 지시문보다 앞에 — 지시문과 import 사이에 다른 줄이 끼면 타겟팅이 깨진다). 모바일/PC 모두 추이-구성비 순서다. 순자산·카테고리별/자산군별 현황·구성비 계산은 전부 `entities/finance/lib/aggregate.ts`의 순수 함수를 공유한다(위젯 계층에 중복 구현 금지). `assetClass`/`market`은 서버 닫힌 enum이라 라벨은 `useMeta()`의 `labelOf('assetClasses'|'markets', code)`로 얻고, L1 카테고리 라벨은 `formatAssetL1CategoryLabel(id)`로 얻는다(위젯에서 직접 라벨 맵을 두지 않는다)
- **가계부 금액 감추기**: 설정 탭 토글(`features/finance/hide-amounts`, localStorage 영구)과 `FinanceHeader` 눈 아이콘(세션 한정 일시 공개, 가계부를 떠나면 해제)이 `shared/lib/hooks/use-amount-hidden.ts` 모듈 스토어(`useSyncExternalStore`)를 공유한다. 자산·수입·소비·저축 탭에서 금액을 표시하는 위젯은 `fmtKrw`/`fmtSignedKrw` 결과를 반드시 `maskIfHidden()`으로 감싼다(새 위젯·새 표시 지점 추가 시 누락 주의). KPI 요약은 `masked`일 때 `RevealableValue`로 값별 보기 버튼을 둔다. 차트 Y축 눈금(만원 축약)과 탭 밖 화면(예산 관리·일괄 등록)은 의도적으로 마스킹하지 않는다. SSR·hydration 첫 렌더는 설정을 읽기 전(`hidden === null`)이라 가린 상태로 그린다 — 실제 금액이 깜빡이지 않게 하기 위함
- **`asset-settings/AssetSettingsPanel`**: `/finance` 설정 탭의 조합 위젯. `features/finance/manage-categories`(카테고리 CRUD)·`manage-accounts`(계좌 CRUD)·`manage-strategy-suggestions`(운용전략 추천 목록 — 계좌관리 아래)·`manage-group`(그룹 멤버·초대)을 `SettingsPageContent`와 동일한 "Surface 카드로 묶기" 패턴으로 나열한다. 화이트리스트 밖 페이지 위젯이라 다른 widget에서 import 금지 — `app/(main)/finance/(dashboard)/settings/page.tsx`(app 레이어)만 마운트한다
