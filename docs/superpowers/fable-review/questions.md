## 항목

묶음 C(04-4·5a·5b·5c) 실행 중 지침서에 기준이 없어 실행 세션이 정한 것과, 이후 태스크 전에 지침서에 적어야 할 것이다. 모두 완료된 태스크라 멈춘 범위는 없다. 정한 내용이 맞는지 확인하고 지침서에 반영해 달라. 실행 기록은 `PROGRESS.md` "묶음 C 실행 기록".

### Q-01 지침서 04에 "판단이 갈릴 때의 기본값" 절이 없다
- 상태: 답변됨
- 묶음·태스크: C / 지침서 04 T5a·T5b
- 걸린 곳: CHARTER "실행 중 질문"은 지침서의 "판단이 갈릴 때의 기본값"으로 스스로 정하라고 하지만, `guides/*.md` 9개 모두 그 절이 없다(`grep -n "판단이 갈릴" guides/*.md` 0건). "하지 말아야 할 것"만 있다.
- 근거: 기본값 없이 정한 것 — (1) 이미 Dialog인 가계부(거래내역·재무계좌·카테고리)·관리자 개인정보 폼도 `FormDialog` 셸로 옮겼다. 결정 1 표가 이들을 "폼 다이얼로그(PC 가운데, 모바일 전체 화면)"로 적은 것을 근거로 했다(`c9da8857`, `77249aab`). (2) 제출 버튼 비활성(`canSubmit`)과 zod 오류 표시가 충돌하는 폼에서 관리자 개인정보는 버튼을 항상 활성으로 두고 제출 시 오류를 보이게 했고, 가계부는 기존 비활성 조건을 유지했다. 두 방식이 섞여 있다.
- 선택지: (A) 04에 기본값 절을 추가해 (1)·(2)를 확정. (2)의 기준 후보는 "형식 오류는 제출 시 필드에 표시, 버튼 비활성은 서버 상태 잠금(월 마감 등)에만". (B) 지금 상태를 예외로 인정.
- 멈춘 범위: 없음
- 답: (Fable) 지침서 04에 "판단이 갈릴 때의 기본값" 절 추가, "폼 구현은 한 가지"에 제출 버튼 규칙 추가, 태스크 5d 추가 — (1) 이미 Dialog인 폼도 `FormDialog` 셸로 옮기는 것이 맞다. (2) 두 방식을 섞어 두지 않는다. 버튼은 진행 중·잠금(월 마감 등)에만 비활성이고 빈 값·형식 오류는 제출 시 필드에 표시한다. 관리자 개인정보 쪽이 기준이고 가계부·자산 기록·`CredentialsCard`·초대 코드 입력을 5d로 맞춘다(`canSubmit` → `locked`). 다른 지침서 8개에는 이 절을 미리 만들지 않았다. 질문이 나오면 그때 추가한다. 커밋 `e9e1000e`.

### Q-02 T7 이후 서버 `fieldErrors`와 실패 토스트의 분담
- 상태: 답변됨
- 묶음·태스크: C / 지침서 04 T4, 02 전역 실패 토스트
- 걸린 곳: 04 "폼 구현은 한 가지"는 "필드에 붙지 않는 오류는 02의 전역 토스트가 띄운다"고 하고, 02(`guides/02-data-layer.md:74`)는 `MutationCache` `onError` 한 곳에서 `detail`을 띄운다. 필드에 붙인 오류를 전역 토스트가 또 띄우지 않게 하는 방법은 어느 쪽에도 없다.
- 근거: 지금(02 전)은 entities mutation hook마다 `onError: toast.error(apiMsg(...))`가 있어 `useAppForm`은 실패 토스트를 띄우지 않고, 매핑은 `MAP_SERVER_FIELD_ERRORS = false`로 꺼 두었다(`shared/ui/form/useAppForm.ts`).
- 선택지: (A) 전역 `onError`가 `fieldErrors`가 있으면 건너뛰고 폼이 필드에 붙인다(필드 없는 폼에서 묻히는 위험). (B) `useAppForm`이 넘기는 mutation에 `meta: { fieldErrors: true }`를 달고 전역 처리가 그 경우만 건너뛴다. (C) 전역은 항상 `detail`을 띄우고 폼은 필드 표시만 추가(이중 알림 허용).
- 멈춘 범위: 없음(T7 착수 전 필요)
- 답: (Fable) 지침서 04 "폼 구현은 한 가지"에 "서버 오류의 분담" 추가, 위험 절 개정, 태스크 5g 추가. 지침서 02 3절 실패 토스트 줄 개정 — 선택지 (C)에 규약 하나를 붙였다. 전역 `onError`는 `fieldErrors`가 있어도 항상 `detail`을 띄우고 `meta` 플래그를 만들지 않는다. `fieldErrors`가 있는 응답의 `detail`은 요약 문장으로 고정해 같은 문장이 두 번 나오지 않게 한다(`../kista-api/docs/superpowers/fable-review/cross-repo.md` B "fable-ui 요청 (2026-11-13)", api 지침서 10의 2-5절·T7에 반영됨 — api 커밋 `3cdbdedca`). 이름이 안 맞는 필드 오류는 `root.server`로 모아 `FormActions`가 버튼 위에 그린다. (A)·(B) 기각 이유는 04에 적었다. 커밋 `e9e1000e`(ui), `79c363f30`(api cross-repo).

### Q-03 "모든 폼이 RHF"의 예외 목록

### Q-04 필수·선택 표기 규칙을 문서 어디에 둘지
- 상태: 답변됨
- 묶음·태스크: C / 지침서 04 T4·T7, 08
- 걸린 곳: 04는 "표기는 `FormField` 한 곳에서 정한다(필수 `*`)"만 적고 선택 필드 표기는 정하지 않았다. `copy.md`에는 이 규칙이 없다.
- 근거: 전환한 폼에서 " (선택)"·"(필수)" 꼬리를 지우고 필수에 `*`를 붙였다. 전환 안 한 곳은 표기가 남아 있다 — `features/strategy/reconfigure-vr/ReconfigureVrSections.tsx:108,138`의 섹션 제목 "투자금 추가 (선택)"·"투자금 인출 (선택)"(04-6 범위). 계좌 등록 스테퍼(`ApiStep`)는 필수 `*` 없이 라벨만 있다.
- 선택지: (A) `copy.md`에 "필수는 `*`(FormField), 선택 꼬리 없음, 섹션 제목의 (선택)은 허용/금지"를 추가하고, 04-6·스테퍼 전환 때 따르게 한다. (B) 선택 필드에도 표기를 두기로 바꾸고 `FormField`에 `optional`을 추가.
- 멈춘 범위: 없음
- 답: (Fable) 지침서 04 "폼 구현은 한 가지" `FormField` 항목 개정, 태스크 6·7 개정 — 선택지 (A). 필수는 `*`, 선택은 표기 없음, `optional` prop 없음. 섹션 제목의 "(선택)"도 쓰지 않는다(`ReconfigureVrSections` 2건은 04-6에서 지운다). 스테퍼의 `*` 누락은 5f에서 `FormField`가 붙인다. 문서 위치는 `copy.md`가 아니라 `a11y.md` "폼" 항목이다(Q-05 답과 같은 곳, shared에서도 로드된다). 커밋 `e9e1000e`.
