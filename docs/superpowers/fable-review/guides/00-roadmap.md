## 4. Fable 없이 실행하는 공통 규칙

원본은 `../kista-api/docs/superpowers/fable-review/guides/00-roadmap.md` 9절이다(착수 전 전제 확인, 유형별 처리, 가드, 배포, 중단 조건의 순서, 스스로 정하는 것과 묻는 것). 그 절을 먼저 읽는다. 아래는 ui에서 달라지는 것만 적는다. api 9절의 유형 U1(외부 문서)·U3(실계좌 실측)·U4(주문 2차 효과)와 마이그레이션 번호, 매매 시간대 배포 규칙은 ui에 해당하지 않는다.

### 4-1. 태스크 착수 전 전제 확인

지침서의 줄 번호·수치는 2026-11-11~13 값이다. 실행 중 드러난 틀린 전제 15건 중 9건이 착수 전 grep 한 줄로 걸러지는 것이었다(`findings/r` 5절).

1. 태스크가 이름으로 든 파일·심볼이 있는지 본다: `git grep -n "<이름>" -- '*.ts' '*.tsx' '*.mjs' | head`. glob에는 반드시 따옴표를 붙이고, 괄호가 든 경로(`"app/(main)/…"`)도 따옴표로 감싼다.
2. **지침서의 완료 판정 명령을 그대로 믿지 않는다.** 지침서는 `grep -rn … --include='*.ts*' .` 꼴로 적었다. 실행할 때는 `git grep -n -E "<패턴>" -- '*.ts' '*.tsx' ':!shared/lib/api-types.ts' ':!*.test.*'` 꼴로 바꾼다. 이유: ① 생성물(`shared/lib/api-types.ts`, `openapi.json`)과 `docs/`가 걸려 0건이 되지 않는 판정이 있다 ② macOS에서 `\b`가 듣지 않는다(`-w`나 문자 클래스를 쓴다) ③ `*.mjs`(scripts)와 따옴표 없는 한글 문구는 원래 패턴이 놓친다. 판정의 뜻("이 코드가 제품에 남아 있지 않다")을 지키는 쪽으로 명령을 고치고, 고친 명령을 그 지침서 보정 절에 적는다.
3. "N개/N곳"은 다시 센다. 숫자가 달라도 태스크의 뜻이 같으면 지금 숫자로 진행한다.
4. 대상이 이미 없으면 그 항목만 건너뛴다. **삭제하는 심볼은 삭제 전에 `git grep -n "<심볼>"`으로 소비처를 보고, 그 파일만 쓰던 export가 고아가 되는지 같은 커밋에서 확인한다**(`isSubviewEntry`를 14분 뒤 따로 지운 일이 있었다. `npm run knip`이 잡는다).
5. 서버 계약을 전제하는 태스크는 필드가 들어왔는지 본다: `git grep -c "<필드명>" -- shared/lib/api-types.ts`. 0이면 서버가 아직이다. 2026-11-14 기준 0건인 것: `fieldErrors`, `allowedActions`, `blockedActions`, `reasonCode`, `reapplyAvailableAt`, `userStatuses`, `trading-cycle-validations`, `ENGINE_RESTARTING`. 이미 있는 것: `GET /api/trading-cycles/{id}`, `listUsers`의 `status` 필터, `CycleHistoryPageResponse`의 `items`·`nextCursor`·`hasMore`.
6. 코인·KIS에 걸친 코드인지 본다(4-2의 V8).

| `app/globals.css:6` `@source not "../docs"` | Tailwind가 `docs/`를 훑지 않게 | `docs/` 밖에 md를 새로 만들지 않는다. 클래스 문자열 예시(`text-[var(--…)]`)가 든 md를 스캔 범위에 두면 dev 서버 CSS가 깨진다 |
| `testing/mockApi.ts` | 전역 `fetch` 교체, 키 `'GET /api/…'` | 02의 3. 새 fetch 래퍼가 `fetch`를 모듈 로드 때 잡아 두면 mock이 듣지 않는다. 호출할 때 `globalThis.fetch`를 읽는다 |

- 문자열이 박힌 것은 같은 커밋에서 고친다. 묻지 않는다.
- **lint 규칙·knip 예외를 느슨하게 해서 통과시키지 않는다.** `eslint-disable` 주석을 새로 달지 않는다. 규칙의 뜻과 부딪히면 그 항목을 지침서가 가리킨 뒤 단계(대개 03)로 미루고, 미룰 곳이 없으면 그 항목만 멈춘다.
- knip에 새로 잡힌 것은 지우는 것이 기본이다(`commands.md`).
- 새 lint 규칙을 넣는 태스크(06의 7, 11의 11, 03의 7)는 위반을 먼저 0으로 만들고 규칙을 켠다. 고의 위반 파일로 규칙이 잡는지 확인한 뒤 되돌린다(07의 5가 한 방식).
- 테스트가 문구·역할을 단언해서 깨지면: 동작이 같고 표기만 바뀐 것은 테스트를 고친다. **요청 바디를 단언하는 테스트(묶음 C의 선행 테스트)가 깨지면 기대값을 고치지 않는다.** 4-5의 1번이다.

### 4-4. 배포와 승인

`main`에 push하면 `server-deploy.yml`이 배포한다. push는 사용자가 요청할 때만 한다. 실행 세션은 커밋까지 하고 완료 보고에 아래를 붙인다. 되돌리는 방법은 `deploy/server/README.md`의 롤백 절이다.

| 변경 종류 | 실행 세션이 준비할 것 | 순서 |
|---|---|---|
| 화면이 같은 리팩토링(01, 02의 1~7, 03, 06의 프리미티브 전환, 07) | typecheck·lint·knip·vitest. 화면 흐름을 건드렸으면 e2e 1회(4-5) | 제한 없음 |

### 4-5. 중단 조건과 확인할 수 없는 것

순서는 api 9-5와 같다: **되돌린다 → 지침서의 대체 경로 → 없으면 그 태스크만 멈추고 사용자에게 묻는다.** ui에서 자주 걸리는 세 가지의 대체 경로는 지침서마다 적지 않고 여기 한 번 적는다.

1. **동작 보존 테스트가 깨진다**(요청 바디 고정, 변이 확인, visual-diff 차이). 기대값·기준 이미지를 고치지 않고 변경을 되돌린다. 차이가 의도한 것(지침서가 "바뀐다"고 적은 것)이면 그 근거 문장을 커밋 메시지에 적고 진행한다.
2. **로컬 api가 필요하다**(`fetch:spec`, `test:e2e`, visual-diff, 인증 흐름 수동 확인). 로컬 api는 임의로 띄우지 않는다. 사용자가 띄운 상태면 쓴다. 아니면:
   - `fetch:spec`이 필요한 태스크(01의 1)는 그 태스크만 멈추고 사용자에게 기동을 요청한다. 대체 경로가 없다.
   - e2e·visual-diff는 api 없이 되는 검증(typecheck·lint·knip·`mockApi` 기반 vitest·변이 확인·`a11y-check`)까지 하고 커밋한다. `PROGRESS.md`의 "e2e 대기" 목록에 커밋 해시와 돌릴 명령을 적는다. 다음에 api가 떠 있는 세션이 묶어서 한 번 돌린다. **e2e 대기가 남은 채로 push를 요청하지 않는다**(화면 흐름·라우팅·문구를 바꾼 커밋에 한해).
   - 부하성 timeout(전체 vitest에서 1~20건)은 실패한 파일만 단독으로 다시 돌려 통과하면 통과로 본다.
3. **실기기가 필요하다**(모바일 뒤로 가기, iOS 키보드, 서비스 워커). Chromium 모바일 에뮬레이션과 390px 스크린샷까지 하고 진행한다. 남은 항목은 `PROGRESS.md`의 "미검증(실기기 필요)" 목록에 적는다. 실기기 확인을 기다리며 멈추지 않는다.
4. **"사용자에게 스크린샷을 보여 확인받는다"**(06의 6, 11의 11 등). 전후 스크린샷을 scratchpad에 만들어 완료 보고에 경로를 적고 커밋까지 한다. 답을 기다리지 않는다. push가 사용자 몫이라 그 전에 되돌릴 수 있다.
5. **다른 세션이 같은 파일을 고치고 있다**(03). 03은 전용 worktree에서만 한다. 착수할 때 `git status`가 깨끗하지 않거나 `main`이 실행 중 앞서가면 그날은 03을 하지 않는다.

## 5. 실행 세션이 헤맨 지점 (`findings/r` 6절에서)

- **삭제한 파일만 쓰던 export를 같은 커밋에서 못 지웠다.** 삭제 커밋 전에 `npm run knip`을 돌린다.
- **같은 원인을 두 커밋으로 고쳤다**(`fmtDate`만 고치고 `fmtDateTime`은 4시간 뒤). 결함을 고칠 때 같은 패턴을 `git grep`으로 전부 찾아 한 번에 고친다.
- **같은 폼을 두 곳에서 조립하게 두었다가 뒤 커밋에서 합쳤다.** 다이얼로그·폼을 옮길 때 소비처가 둘 이상이면 처음부터 조립을 한 컴포넌트에 둔다.
- **프리미티브의 API가 세 번 바뀌었다**(`FormDialog`). 프리미티브는 소비처 2개 이상을 실제로 옮겨 본 뒤 커밋한다(06의 1이 시범 전환 2개를 요구하는 이유).
- **비동기 완료가 늦게 도착하는 경로를 놓쳤다**(닫힌 뒤 도착한 `onDone`). 닫기·이동을 부르는 콜백은 "닫힌 뒤 도착", "다시 연 뒤 이전 회차가 도착" 두 케이스를 테스트에 넣는다.
- **묶음을 끝낸 뒤 문서가 낡았다**(`app.md:40`). 4-3의 문서 행.
