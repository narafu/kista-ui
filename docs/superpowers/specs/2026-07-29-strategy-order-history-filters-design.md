# 전략 주문 내역 필터 설계

## 목표

전략 상세의 주문 내역에서 방향, 주문 유형, 상태를 함께 필터링할 수 있게 한다. PC와 모바일에서 같은 필터 구조와 선택값을 제공하며 기존 기간 조회 및 페이지 크기 기능은 유지한다.

## 동작

- 방향, 유형, 상태 필터의 초기값은 모두 `전체`다.
- 여러 필터가 선택되면 AND 조건으로 적용한다.
- 방향 선택지는 `전체`, `매수`, `매도`다.
- 유형 선택지는 `전체`, `LIMIT`, `LOC`, `MOC`다.
- 상태 선택지는 `전체`, `예정`, `접수`, `체결`, `부분체결`, `취소`, `실패`다.
- 필터는 기간 조건으로 조회된 주문 전체에 적용한 후 페이지네이션한다.
- 필터가 바뀌면 현재 페이지를 1페이지로 초기화한다.
- 기간 내 주문 자체가 없으면 기존 `주문 내역이 없습니다.`를 표시한다.
- 주문은 있지만 선택한 필터 결과가 없으면 `조건에 맞는 주문이 없습니다.`를 표시한다.

## UI

필터 행은 기존 기간 및 페이지 크기 컨트롤 아래에 별도 배치한다. 기존 shadcn Select 스타일을 사용해 화면 내 다른 입력과 시각적으로 연결한다.

- PC: 방향, 유형, 상태 드롭다운을 콘텐츠 폭에 맞춘 한 행으로 배치한다.
- 모바일: 세 드롭다운을 동일 너비의 3열로 배치한다. 각 트리거에는 현재 값과 아래쪽 화살표가 표시되며 가로 스크롤을 만들지 않는다.
- 각 드롭다운에는 `방향`, `유형`, `상태` 접근성 레이블을 제공한다.

## 구조

`StrategyOrderHistory`가 필터 상태를 소유한다. 필터 컨트롤은 주문 내역 전용 프레젠테이셔널 컴포넌트로 분리해 레이아웃과 선택지 정의를 격리한다. 서버 API와 React Query 키는 변경하지 않는다.

데이터 흐름은 다음 순서를 따른다.

1. 기간 조건으로 주문을 조회한다.
2. 방향, 유형, 상태 조건을 AND로 적용한다.
3. 필터 결과의 총 페이지 수를 계산한다.
4. 현재 페이지에 해당하는 주문만 테이블에 표시한다.

## 테스트

- 세 필터가 기본적으로 전체 주문을 유지하는지 검증한다.
- 방향, 유형, 상태 필터가 각각 결과를 제한하는지 검증한다.
- 세 조건이 AND로 결합되는지 검증한다.
- 필터 변경 시 1페이지로 초기화되는지 검증한다.
- 원본 주문이 있지만 필터 결과가 없을 때 전용 빈 상태를 표시하는지 검증한다.
- 타입 검사와 관련 Vitest 테스트를 실행한다.
